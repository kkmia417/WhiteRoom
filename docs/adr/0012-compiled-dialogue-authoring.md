# ADR-0012: Compile ordered chapter CSV sources during Unity import

Status: Accepted<br>
Date: 2026-09-26<br>
Related: [Issue #85](https://github.com/kkmia417/WhiteRoom/issues/85)<br>
Japanese counterpart: [日本語版](0012-compiled-dialogue-authoring.ja.md)

## Context and problem statement

The prototype manuscript contains 10,648 rows and 14 chapters in a 1.1 MB CSV.
Authors must navigate the entire file, and every repository construction parses
text and validates the complete graph. Splitting files alone leaves that runtime
cost intact. Existing saves and presentation depend on stable IDs and extra columns.

## Decision drivers

- Preserve all story values, row order, published IDs and save compatibility.
- Reduce startup parsing and temporary allocations before introducing streaming.
- Keep standard CSV editing and reuse Talk System parsing and validation.

## Decision outcome

### Author ordered chapter sources

An explicit `.dialogue` JSON manifest lists CSV asset paths in reading order.
Each chapter has the same header; sources live outside Resources. The manifest
is the only assembly order, and CSVs are the only editable narrative authority.

**Rationale**: Chapter-sized changes are easier to find and review; stable order
preserves trigger precedence and enumeration across files.
**Impact**: Moving sources requires updating the manifest. Cross-chapter links
remain ordinary IDs. All columns, including unknown presentation columns, survive.

### Compile through the package importer

Talk System imports the manifest using its existing codec and validator, validates
the combined graph, and serializes a compiled asset. Runtime creates ID/trigger
indexes without CSV parsing or graph validation. Import dependencies invalidate
compiled data after source edits. Invalid imports cannot produce usable repositories
and are rejected by a build gate. Custom single-CSV loaders remain supported.

**Rationale**: Parsing belongs to Talk System and errors should surface before play.
**Impact**: The package gains a reusable compiled asset, importer and loader;
WhiteRoom only selects the loader in Setup. Extra columns and source row order
need serialization tests. Performance evidence separates index construction from
Unity asset loading. Preview exports are temporary, never a second source of truth.

## Benefits

- Smaller authoring files without story or save migrations.
- No CSV parsing or graph validation in the default player startup path.
- Whole-scenario validation catches duplicate IDs and cross-file broken links.

## Trade-offs

- All dialogue rows still reside in memory; streaming remains future work.
- Imported binary data adds Library cache/build output; it is regenerated by Unity.
- Manifest paths need maintenance; missing sources fail loudly.
- Unity must import edits before play; automatic dependency tracking mitigates drift.

## Rejected alternatives

| Alternative | Why rejected |
| --- | --- |
| Split and merge CSVs at startup | Improves editing but retains parsing and graph-validation cost. |
| Introduce lazy chapter streaming now | Adds lifetime and save/branch loading rules beyond this bounded improvement. |
| Add a project-side parser | Duplicates package ownership and risks schema drift. |
| Commit another hand-edited compiled representation | Creates two competing narrative sources. |

## Development rule integration

- Validate full manifests on import and before builds, using the package validator.
- Test serialization, extra columns, source invalidation, invalid graphs and routes.
- Compare migrated rows against the original manuscript before removing it.
- Keep generated import artifacts out of source control; document chapter editing.

## Notes

- No Addressables, lazy loading, story editing, or save-schema changes here.
- Reconsider partitioned runtime assets when measured deserialization or resident
  memory dominates startup after removing parsing.
