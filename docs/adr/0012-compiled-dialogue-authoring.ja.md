# ADR-0012: 順序付きの章別CSVをUnityインポート時にコンパイルする

ステータス: Accepted<br>
日付: 2026-09-26<br>
関連: [Issue #85](https://github.com/kkmia417/WhiteRoom/issues/85)<br>
English canonical file: [English](0012-compiled-dialogue-authoring.md)

## コンテキストと問題提起

プロトタイプの原稿は14章、10,648行、約1.1MBの単一CSVである。
編集時には全体を探す必要があり、Repository構築のたびに全文解析とグラフ検証を行う。
ファイル分割だけでは実行時負荷が残る。既存セーブと演出は安定したIDと拡張列に依存する。

## 決定要因

- 台詞の全値、行順、公開済みID、セーブ互換性を維持する。
- ストリーミング導入に先立って起動時の解析と一時割り当てを減らす。
- 通常のCSV編集を維持し、Talk Systemの解析・検証を再利用する。

## 決定結果

### 章別ソースの順序を明示する

`.dialogue` JSONマニフェストにCSVのアセットパスを読む順序で記載する。
各章は同じヘッダーを持ち、Resourcesの外に配置する。結合順序はマニフェストのみが定義し、
編集可能な物語の正本はCSVのみとする。

**根拠**: 章単位なら変更を探しレビューしやすい。順序の維持はトリガー優先順位と列挙順を守る。
**影響**: ソース移動時はマニフェストを更新する。章をまたぐ参照は既存IDを使い、未知の演出列も含め全列を維持する。

### パッケージのImporterでコンパイルする

Talk Systemの既存CodecとValidatorでマニフェストを読み、全体のグラフを検証して
解析済みアセットをシリアライズする。実行時はCSV解析とグラフ検証をせずIDとトリガーの索引を作る。
依存ソースの編集は再インポートを起こす。不正なインポートからRepositoryは作れず、ビルドゲートでも拒否する。
任意の単一CSVを読む既存Loaderは維持する。

**根拠**: 解析責務はTalk Systemにあり、誤りはプレイ前に検出するべきである。
**影響**: パッケージに汎用の解析済みアセット、Importer、Loaderを追加する。
WhiteRoomはSetupでLoaderを選ぶ。拡張列と行順のシリアライズをテストする。
性能測定では索引構築とUnityのアセット読み込みを区別する。プレビュー出力は一時ファイルであり別の正本にしない。

## 利点

- 物語やセーブの移行なしに編集ファイルを小さくできる。
- 標準の起動経路でCSV解析・グラフ検証を行わない。
- 全体検証により重複IDやファイル間の参照切れを検出できる。

## トレードオフ

- 全行は引き続きメモリに保持する。ストリーミングは将来の課題とする。
- Libraryとビルドにインポート済みデータが増えるが、Unityが再生成する。
- マニフェストのパスを維持する必要があり、欠落は明示的に失敗させる。
- プレイ前にインポートが必要になるが、自動依存追跡で更新漏れを抑える。

## 不採用の選択肢と根拠

| 選択肢 | 不採用理由 |
| --- | --- |
| 起動時に章別CSVを結合する | 編集は改善するが解析とグラフ検証の負荷が残る。 |
| 今回、章の遅延ロードも導入する | 寿命管理、セーブ復元、分岐先読み込みの規則が範囲を超える。 |
| ゲーム側に別のParserを追加する | パッケージの責務と重複しスキーマがずれる。 |
| 解析済み表現も手編集してコミットする | 物語の正本が二つになる。 |

## 開発ルール連携

- インポート時・ビルド前にマニフェスト全体をパッケージのValidatorで検証する。
- シリアライズ、拡張列、依存ソース更新、不正なグラフ、各ルートをテストする。
- 元原稿を削除する前に移行後の全行を比較する。
- インポート生成物をコミットせず、章別編集手順を文書化する。

## 注記

- Addressables、遅延ロード、物語の編集、セーブスキーマの変更は対象外。
- 解析除去後もデシリアライズ時間や常駐メモリが起動負荷の主要因なら、実行時アセット分割を再検討する。
