# Player screenshots

Japanese counterpart: [日本語版](screenshots.ja.md)

WhiteRoom provides one full-resolution PNG capture from the `SHOT` command or the
assignable `NovelGameBootstrap.screenshotShortcut` (`F12` by default). This use case
is separate from save thumbnails: it does not resize, crop, impose the thumbnail byte
limit, or write into save-slot sidecars.

## Capture and UI contract

- The gameplay background and character stage are always included.
- The dialogue/name/text/choices are included exactly when they are currently visible.
  A screenshot requested by shortcut while Hide Message is active preserves and
  captures that hidden state.
- The command bar, its tooltip, and transient notifications are excluded for the
  capture frame and restored afterward.
- Auto, Skip, dialogue visibility, focus, and `Time.timeScale` are not changed. If a
  command-bar control owned focus, it is restored when still active.
- Only one capture may run at a time. Repeated commands/shortcut input returns a
  non-fatal Busy result; command availability returns after completion.
- Every source `Texture2D` is destroyed after encoding, including failure paths.

## Storage and platform policy

`FileScreenshotStorage` writes under
`Application.persistentDataPath/Screenshots`. File names use UTC time with
milliseconds, for example `WhiteRoom_20260730_120102_345Z.png`. Existing files are
never overwritten: a collision adds `_001`, `_002`, and so on, and the adapter writes
with create-new semantics. File names are generated by policy; no player-entered path
is accepted.

Desktop and native players use the file adapter. WebGL player builds report the
capability as unsupported and disable the command with a reason. Success notification
contains both the generated file name and destination directory. Unsupported, Busy,
capture, encoding, and storage failures are classified and shown as non-fatal results;
none changes dialogue or save state.
